Live payment flow

1. Clerk identifies disconnectionThe clerk determines that the Terminal is unavailable
2. Select Stripe QRChoose Stripe QR directly from the payment methods
3. Create Checkout SessionThe backend locks the order amount and returns a URL
4. Display payment QRThe POS encodes the Stripe Checkout URL as a QR code
5. Customer scans and paysThe webhook verifies and updates the payment idempotently
6. POS shows successOrder polling leads into the existing success screen
Key rule: amount, currency, and order ownership are read by the backend. The POS never supplies a trusted final amount. Webhooks confirm payment; POS polling only refreshes the user experience.

Recommendation: use Stripe Checkout Sessions

Create an order-specific Session for every payment attempt. Stripe returns a hosted Checkout URL, which the POS encodes as a QR code.

Source of truth
Why not reuse a Payment Link: a reusable store-level link cannot reliably bind the amount to one order. Checkout Sessions provide one URL per payment attempt and support metadata, expires_at, payment_status, and PaymentIntent reconciliation.
